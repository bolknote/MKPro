# Erasure-aware selector/data layout

A private runtime selector can also supply an ordinary literal when its final
callee address equals that literal. This is an intersection of data and address
constraints, not a recognition of any program, function name or chosen constant.

The original layout-then-erase alternative remains available. A second
transaction removes the literal before solving geometry. An immutable companion
may temporarily move away from its decoded address; it receives an explicit
absolute-target obligation and a deferred selector reconciliation. Observable
preload data is never changed to make geometry convenient. Retunable companions
still require the existing independent data-projection certificate.

The intermediate artifact is not publishable. Acceptance requires all of:

- Original independent entry proofs for every selector charge.
- Exact transport of command identities, indirect aliases, external entries,
  matched return frames and the empty-stack return target across the erasure.
- Final authoritative layout proof, including every deferred selector debt.
- Re-derived final literal/address equality and stack, X1 and X2 convergence at
  every charge, not a trusted provenance marker alone.
- Strictly fewer final cells, including all introduced padding or bridges.

The solver uses the shortened component lengths and the actual final addresses.
At most the erased cell count minus one can be spent on geometry. Existing
deterministic subset/anchor limits apply; the search is not enlarged globally.

The selector data/literal compiler-and-ROM regression includes an immutable
selector whose target lies after the erased literal, varied entry offsets, full
stack/data observations and a decimal-entry probe. Stale and ambiguous preloads,
observable displaced inputs and physical last-X remain negative cases.
