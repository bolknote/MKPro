# Finite-epoch observation recovery and register-chain composition

A stored finite state and the X value recalled from it have distinct lifetimes.
After a proved true predicate fallthrough the consumer may need the original X
without needing a restored physical carrier. The finite representation pass
therefore considers exact unary decoders and exponent-only recovery alongside
its existing exponent/store and literal/store restorations.

## Proof obligations

- Intersect every finite row and exact call/return context at the insertion.
- Reject external entries, taken-branch entry shadows, unknown epochs and aliases.
- Prove the complete finite decoder table with exact decimal arithmetic.
- Keep the carrier encoded after an X-only decoder. Subsequent reads, resumes
  and exits retain their independent register-relation obligations.
- Exponent entry does not overwrite last-X; unary arithmetic may overwrite it.
  Propagate X1 and X2 inequality until independently proved convergence.
- Exponent-only recovery requires an immediately following original store to
  close number entry. A following digit otherwise extends the exponent rather
  than starting a fresh mantissa; numerical X equality alone cannot authorize it.
- Charge every emitted command and retain only completely proved artifacts.

The historical restoration subset search retains its independent 32-attempt
budget. A second cost-ordered lane may compose observations with restorations.
Two alternatives at the same insertion cannot be selected together. Equal-cost
solutions retain the historical witness; only a strictly cheaper repair replaces it.

Reaching-definition web allocation can then use an opt-in bounded two-color
interchange. If greedy coloring fails, it exchanges complete connected components
of two colors. Every fixed home and list-color domain is checked before an atomic
commit, and every interference edge is validated again. Work counts graph/domain
visits across the complete solver invocation; exhaustion is inconclusive and
publishes no partial assignment. The production web allocator allows 4096 visits;
ordinary exact/source allocation keeps its historical behavior by default.

Neither mechanism uses source names, game identities or selected game constants.
The game source and its input protocol are unchanged. The full compiler remains
responsible for final layout, selector digits, memory aliases and return identities.
