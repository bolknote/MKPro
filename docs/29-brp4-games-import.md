# Игры и развлечения БРП-4

## Источники и границы импорта

Проверен документированный игровой раздел «Электроники БРП-4»: программы
31–48, 50 и 51. Включены самостоятельные редакции знакомых игр, а также
числовые фокусы, генераторы и помощники из этого раздела. В каталоге они имеют
соответствующие `kind`, а общая коллекция — `brp4`.

- [Дампы БРП и дизассемблер myak555 / MK-52_Resurrect](https://github.com/myak555/MK-52_Resurrect/tree/main/MK-52_Sample_Programs/BRP%20Expansion%20Modules).
- [Исходный BRP4-2.BIN на зафиксированной ревизии](https://github.com/myak555/MK-52_Resurrect/blob/84693a122a2737169257edf6565b1aa8814b742e/MK-52_Sample_Programs/BRP%20Expansion%20Modules/BRP4-2.BIN).
- [«Кон-Тики»: указатель руководств и полного текстового дампа БРП-4](https://arbinada.com/pmk/pages/01057-library-docs.html).
- [Публичный архив руководств МК-52, БРП-2, БРП-3 и БРП-4](http://arbinada.ddns.net/pmk-files/manuals_docs/%d0%ad%d0%bb%d0%b5%d0%ba%d1%82%d1%80%d0%be%d0%bd%d0%b8%d0%ba%d0%b0%20%d0%9c%d0%9a-52%20%d0%91%d0%a0%d0%9f-2%20%d0%91%d0%a0%d0%9f-3%20%d0%91%d0%a0%d0%9f-4%20-%20%d0%a0%d1%83%d0%ba%d0%be%d0%b2%d0%be%d0%b4%d1%81%d1%82%d0%b2%d0%b0%20%d0%b8%20%d1%81%d1%85%d0%b5%d0%bc%d1%8b.zip).

Дамп микросхемы опубликован Сергеем Фроловым. Пакет руководств содержит
`mk-52.brp-4.rukovodstvo_po_ekspluatacii.odt` и `mk-52.brp-4.dump.zip`.
Байты извлечённых программ сверены и с двоичным файлом GitHub, и с
дизассемблированными файлами `brp4p2_original` из второго архива.
Авторство самих программ в руководстве не указано; авторство дампа не
приписывается играм.

В репозиторий добавлены текстовые листинги, карточки и проверочная выборка
байт-кода. Руководства, сканы, архивы и полные дампы ПЗУ в него не входят.

В сравнении учитывались и мнемоники, и байты. Завершающие нули загрузочного
блока сами по себе не образуют новый вариант. Пять совпавших записей получили
ссылку на БРП-4 в карточках и в поле источника манифеста.

## Извлечение и точность

Использован `BRP4-2.BIN`, то есть бытовая/игровая половина микросхемы БРП-4,
переключатель в положении 2. Перемычка П1 выбирает другую библиотеку,
предположительно «Гео»; это отдельный набор, здесь не импортированный.

SHA-256 двоичного файла:

```text
2b6c90c4a889fb783d160bb884d8c3697ee6ff62fbb96ce2fcb067077cd94347
```

Для адреса загрузки `A` из руководства:

```text
length = A % 100
start = floor((floor(A / 100) % 10000) / 2)
physical(a) = 7 * floor(a / 7) + ((a + 6) % 7)
program[i] = ROM[physical(start + i)]
```

Это перестановка внутри семибайтовых групп, реализованная в `ConvertBRP_Ru.py`
источника. Первая цифра адреса загрузки не участвует в этой арифметике.
В архивном текстовом дампе адреса начинаются с `2`, в руководстве — с `1`;
выбранные начальная позиция и длина совпадают.

[Проверочная выборка](../tests/emulator/fixtures/brp4-games.json) хранит для
каждой записи номер, адрес, исходные байты, SHA-256 и явные замены. Полные
длины блоков и завершающие нули сохранены. Исключение в коде ровно одно:
у №47 байт по адресу 18 заменён с `49` (`хП9`) на `69` (`Пх9`) по инструкции.

## Уточнения к руководству

- **№33:** словесные правила говорят о проигрыше взявшего последний предмет,
  но алгоритм использует обычные позиции Уитхоффа, а контрольный пример
  объявляет ПМК победителем при конечном нуле. При равных кучках ПМК выдаёт
  этот сигнал, сохраняя последние остатки в регистрах. Карточка объясняет
  фактическое поведение.
- **№36:** в основном тексте заголовок ошибочно набран как «программа 26»;
  оглавление и адрес однозначно относят её к №36.
- **№39, №40:** перед номерами есть отдельная остановка с количеством чисел
  (`5` или `6`). После последнего номера следующую команду `КБП0` продолжать
  не следует: новая выборка начинается с `В/О D С/П`.
- **№44:** название отсылает к Конвею, но руководство задаёт рождение при двух
  соседях и выживание при одном или двух на поле из 11 клеток. Карточка не
  выдаёт этот вариант за стандартную «Жизнь».
- **№45:** ввод длины выполняется через X, программа сама заполняет служебные
  регистры. После сообщения `π` о штрафе нужен ещё один `С/П`, возвращающий
  обычную остановку для ввода следующей пары.
- **№47:** глубина моря хранится в `Rb`, а не в занятом координатой `R6`, как
  написано в тексте. В карточке даны числовые сигналы `−1`, `−2` вместо
  сложных буквенных заготовок; это данные `Rc`, `Rd`, не изменение кода.
- **№48:** код проверяет счётчик после уменьшения и до расчёта выстрела.
  Из исходных десяти единиц фактически доступны девять результативных
  выстрелов; десятый ввод показывает итог. Порог попадания — строго меньше
  2°, скорости целей — 15–34 узла, начальные пеленги — 100–119°.
- **№50:** рекомендованные мощности в тексте и пример отличаются; карточка
  точно воспроизводит пример с 500 л. с. Для сигнала окончания топлива
  используется числовое значение `Rc=−1`.
- **№51:** сохранены модуль расхода, его ограничение 150 кг/с и историческая
  модель посадки. Это импорт ПЗУ; физическая модель заново не разрабатывалась.

## Проверка

```sh
node tests/emulator/brp4-games.cjs
node scripts/validate-games-catalog.cjs
```

[Проверка в эмуляторе](../tests/emulator/brp4-games.cjs) загружает каждый
доставленный листинг, сравнивает его с исходными байтами и указанными
заменами, затем набирает подготовку из самой карточки клавишами МК-61.
Прямой записи состояния регистров средствами тестового компьютера нет.

Проверены контрольные примеры всех 15 записей, полные партии Баше,
Цзяньшицзы и Нима, оценки угадывания числа, оба режима билетов, оба генератора
на всех 31 допустимых днях, поколения клеточного автомата, манёвры и
сигналы симуляторов, полная торпедная партия и исходные особенности
окончания. Независимые проверки используют ним-сумму, суммы цифр билетов,
правило синусов для перехвата и формулы первого шага дирижабля.
