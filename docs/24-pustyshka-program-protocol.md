# Программная запись и чтение скрытой памяти МК-61

7 сентября 2026 года. Получен непрерывный программный цикл: запись через
«пустышку», перезапись всех обычных регистров, вычисление и повторное чтение.
Промежуточные остановки, ручные нажатия и изменения ПЗУ не требуются.
Проверка выполнена в JavaScript- и C++-реализациях микрокодного эмулятора
этого репозитория. На физическом МК-61 эти последовательности пока не проверены.

Механизм ложной метки разобран в [предыдущем эксперименте](./23-pustyshka-hidden-memory-experiment.md).
Ниже приведены **новые программные** последовательности; прямой перенос
старых ручных последовательностей не работал.

Дополнение от 8 сентября: запись сохраняет также четвёртое слово Q за W.
Приведённые ниже способы чтения по-прежнему дают одно полное или три коротких
числа; [новый эксперимент](./25-pustyshka-capacity.md) отделяет эту доступность
от физической ёмкости памяти.

## Два варианта использования

| Вариант | Что сохраняем и получаем | Запись | Чтение |
| --- | --- | ---: | ---: |
| Одно число | Последнее записанное обычное десятичное число; проверены восемь цифр, оба знака и порядки −99…99 | 13 ячеек | 7 ячеек |
| Три коротких числа | Три целых числа от 0 до 999, возвращаемые одновременно в стек | 13 ячеек | 11 ячеек |

Размеры включают `В/О`. Каждый вызов `ПП адрес` дополнительно занимает две
ячейки в вызывающей программе. Запись общая; два варианта чтения альтернативны.
Минимальность последовательностей не доказана.

**Проверенное размещение: чтение с адреса 06, запись с адреса 21.** Адреса
здесь десятичные, коды команд шестнадцатеричные. Перенос на произвольный адрес
не является установленным свойством: в поисковых опытах результат зависел
от размещения. Для включения в другую программу необходимо проверить её
окончательную компоновку целиком. Причина всех зависимостей от адресов ещё
не разобрана; одного соблюдения границы кратности адреса здесь не заявляется.

## Запись: X → скрытая память

Вызов: поместить число в X и выполнить `ПП 21`.

| Адрес | Код | Команда |
| --- | --- | --- |
| 21 | `49` | `X→П9` |
| 22 | `0D` | `Сх` |
| 23 | `3A` | `К ИНВ` |
| 24 | `35` | `К {x}` |
| 25 | `14` | `↔` |
| 26 | `69` | `П→X9` |
| 27 | `25` | `F ↻` |
| 28 | `0D` | `Сх` |
| 29 | `0E` | `В↑` |
| 30 | `0E` | `В↑` |
| 31 | `0E` | `В↑` |
| 32 | `10` | `+` |
| 33 | `52` | `В/О` |

`F ↻` — циклический сдвиг стека, код `25` (нажатия `F`, `В↑`).

После возврата:

- Р9 содержит входное число; остальные обычные регистры сохранены.
- X, Y, Z, T и X1 равны нулю. Их прежнее содержимое уничтожено.
- Три скрытых слова сдвинуты: `[U, V, W] → [входное X, U, V]`.

Таким образом, U — самое новое число, W — самое старое из трёх, доступных
приведённому ниже чтению. Запись не выбирает произвольный скрытый регистр.
Уточнённый сдвиг четырёх слов: `[U, V, W, Q] → [входное X, U, V, W]`.
Четвёртая запись переносит первое число в Q; пятая вытесняет его и оттуда.
Прежнее утверждение о потере первого числа при четвёртой записи было ошибочным.
Р9 нужен только внутри вызова; между вызовами программа может использовать
его для других целей.

Хвост `Сх В↑ В↑ В↑ +` очищает видимый стек и X1 после обмена с ложной меткой.
Оставлять промежуточную «пустышку» для последующих обычных команд нельзя.

## Чтение одного полного числа

Вызов: `ПП 06`. Получаем последнее записанное число U в X.

| Адрес | Код | Команда |
| --- | --- | --- |
| 06 | `0D` | `Сх` |
| 07 | `3A` | `К ИНВ` |
| 08 | `35` | `К {x}` |
| 09 | `25` | `F ↻` |
| 10 | `00` | `0` |
| 11 | `10` | `+` |
| 12 | `52` | `В/О` |

X1 после возврата равен нулю. Прежнее содержимое вычислительного стека
считать уничтоженным. Обычные регистры и скрытые слова сохранены;
чтение можно повторять. `0 +` удаляет служебное значение из X1.

Этот вариант вернул в том числе `−1,2345678·10^−42`, которое не удавалось
прочитать старой ручной последовательностью. В проверках использованы
нормальные десятичные числа: шестнадцатеричные мантиссы, необычные знаки,
«сверхчисла» и побитовое сохранение всех разновидностей нуля сюда не входят.

Физически новая запись сохраняла все три полных слова независимо.
Однако произвольное чтение каждого из трёх полных чисел не получено:
данный вариант читает только U. Это пока один дополнительный доступный
регистр полного числа.

## Одновременное чтение трёх коротких чисел

Этот вариант поставить по адресу 06 **вместо** предыдущего.
Вызов: `ПП 06`.

| Адрес | Код | Команда |
| --- | --- | --- |
| 06 | `0D` | `Сх` |
| 07 | `3A` | `К ИНВ` |
| 08 | `35` | `К {x}` |
| 09 | `14` | `↔` |
| 10 | `0E` | `В↑` |
| 11 | `0E` | `В↑` |
| 12 | `0E` | `В↑` |
| 13 | `0E` | `В↑` |
| 14 | `00` | `0` |
| 15 | `10` | `+` |
| 16 | `52` | `В/О` |

После последовательной записи `123`, `456`, `789` возвращается:

| X | Y | Z | T | X1 |
| ---: | ---: | ---: | ---: | ---: |
| 123 | 456 | 789 | 789 | 0 |

В общем виде X=W, Y=V, Z=U, T=U. Скрытые слова и все обычные регистры
сохранены. Повторный вызов возвращает те же три числа.

Для сохранения результатов в Р0, Р1, Р2 можно выполнить
`X→П0 F ↻ X→П1 F ↻ X→П2`. Эти последующие сдвиги снова меняют X1;
нулевой X1 обещан именно в момент возврата из подпрограммы чтения.

Четвёртый `В↑` перед `0 +` существенен: ввод цифры после `В↑` не поднимает
стек. Вариант с тремя `В↑` и хвостом `0 +` теряет старейшее число.
Для чисел длиннее трёх цифр этот способ чтения не даёт трёх независимых
результатов, даже когда в скрытых словах записаны разные полные числа.

## Самодостаточный пример

Файл [pustyshka-demo.hex](../tests/emulator/fixtures/pustyshka-demo.hex)
содержит все 105 кодов, начиная с адреса 00. После загрузки: `В/О`, `С/П`.
Числовые регистры заранее заполнять не нужно.

Программа сама вводит и сохраняет `123`, `456`, `789`, обнуляет **все 15
обычных регистров**, вычисляет `(2 + 3)²`, читает скрытые значения и
останавливается с Р0=123, Р1=456, Р2=789. Счётчик после остановки равен 87.
Запись вызывается через обёртку на 34: `ПП 21 В/О`, поэтому одновременно
проверяются два уровня возвратов из подпрограмм.

Неисполняемые промежутки заполнены различающимися контрольными байтами.
Не следует запускать их отдельно: они нужны для обнаружения порчи памяти.
Исполняемые команды и адреса задаёт `makeProgram()` в
[probe-pustyshka-program.cjs](../tests/emulator/probe-pustyshka-program.cjs).

Два других файла предназначены для проверок: исходные числа помещаются
в Ра, Рb, Рc, затем программа записывает их, стирает обычные регистры
и трижды читает результат.

- [pustyshka-triple.hex](../tests/emulator/fixtures/pustyshka-triple.hex):
  результаты трёх чтений в Р0…Р8; счётчик после остановки 92.
- [pustyshka-scalar.hex](../tests/emulator/fixtures/pustyshka-scalar.hex):
  последнее число из Рc возвращается в Р0, Р1, Р2; счётчик после остановки 80.

## Что это даёт оптимизатору

Практическое применение — временно освобождать обычные регистры от редко
используемых значений. Например, сохранить три счётчика с доказанным
диапазоном 0…999, использовать их обычные регистры для промежуточного расчёта,
затем вернуть все три счётчика. Для длинного числа аналогично освобождается
один регистр.

Цена — 24 ячейки общих подпрограмм для трёх коротких чисел либо 20 для
одного полного, плюс вызовы и получение входных значений. Поэтому это
обмен программной памяти и времени на регистры, а не установленное ускорение
или сокращение программы. Выгода зависит от того, какое повторное вычисление
или другое сохранение удастся убрать.

Для автоматического применения нужно учитывать уничтожение стека и X1,
временный Р9, порядок трёх записей, диапазоны значений и размещение кода.
Полезно группировать сохранения и восстановления на границах крупных
вычислений. Проход компилятора в этом эксперименте не добавлялся.

## Воспроизведение и границы проверки

Из корня репозитория:

```sh
node tests/emulator/probe-pustyshka-program.cjs

c++ -std=c++20 -O3 -I native/include \
  tests/emulator/probe-pustyshka-program.cpp \
  native/src/emulator/mk61.cpp native/src/emulator/rom.cpp \
  -o /tmp/mk61-pustyshka-program-verify
/tmp/mk61-pustyshka-program-verify
```

JavaScript-проверка сопоставляет не только читаемые значения, но и все
12 тетрад каждого результата и скрытого слова. Отдельно проверяются обычные
регистры, стек при входе с посторонними значениями и повторные вызовы.
Нативный проверяющий код использует только публичный API эмулятора;
скрытая память ни в одном прогоне не заполняется со стороны проверяющего кода.

Успешно прошли 1000 наборов из трёх коротких чисел: каждое значение 0…999
встречается в каждом из трёх мест, но все миллиард сочетаний не перебираются.
Также прошли 310 случаев полного числа: граничные значения и 300 чисел
с воспроизводимой псевдослучайной мантиссой и порядком. Каждый такой прогон
выполняет три чтения; чередуются радианы, градусы и грады, а часть прогонов
начинается с посторонних больших и отрицательных чисел в стеке. Отдельно
прошёл самодостаточный пример без предварительной загрузки числовых данных.

В конце каждого прогона проверяются ожидаемый адрес остановки и все 105
кодов программы. Запрещать любые временные обмены с программной дорожкой
было бы ошибкой: выборка обычных команд тоже переносит пакеты между M и R
через C9. Проверяется восстановленное содержимое программы при штатной
остановке вместе с фактическими результатами её исполнения.

Успех этих прогонов не доказывает совместимость с произвольными
недокументированными операциями, другой компоновкой или другими моделями ПМК.
Результат относится к МК-61 и приведённым программам на его исходном ПЗУ.
